# composition — 组合根（Composition Root）

> 整个插件的装配车间。唯一一个"什么都可以引用"的分层：把散落在各处的指令、服务、数据表接线到 koishi Context 上。

## 这个分层负责什么

- **指令装配**：汇总 interfaces 各分组指令数组并批量注册（指令集.ts）
- **服务装配**：汇总各上下文 application 层服务并批量注册（服务集.ts）
- **管理指令装配**：admin 指令注册（管理集.ts）
- **数据库装配**：各上下文数据表 model 的 `ctx.model.extend` 声明，及 `declare module "koishi"` 的 Tables 类型扩展（数据库服务.ts）

## 这个分层不负责什么

- 任何业务逻辑、指令定义、表结构定义本身——那些属于各上下文，这里只做"接线"

## 文件结构

```
composition/
├── index.ts           # barrel
├── 指令集.ts           # 文游指令集(ctx) —— 注册玩家指令
├── 服务集.ts           # 文游服务集(ctx) —— 注册 cron/后台服务
├── 管理集.ts           # 文游管理集(ctx) —— 注册管理员指令
└── 数据库服务.ts        # 扩展 Koishi 数据表：加载玩家相关表/联军相关表/军事相关表/地形相关表/全球数据表/服务表
```

## 装配模式

统一借助 [infrastructure/plugin-loader](../infrastructure/) 的 `批量加载插件(ctx, 插件列表, 标签名)`：

```ts
const 生产插件列表 = [基础指令, 联军指令, 生产指令, 地区指令, 军事指令];

export function 文游指令集(ctx: Context) {
    批量加载插件(ctx, 生产插件列表, "文游指令集模块");
}
```

新增上下文服务/指令分组时，只需在对应 集文件 的列表里展开其 `<域>服务列表` / `<域>指令` 数组。

## 依赖规则（fallow 强制）

- **唯一全权限分层**：允许引用一切上下文深层模块、interfaces、shared、config、infrastructure
- 入口 `src/index.ts` 只引用 composition（加上配置初始化），不直接碰业务模块

## 命名约定（本层特有）

| 对象 | 规则 | 示例 |
|---|---|---|
| 装配文件 | 中文 +「集」后缀 | 指令集.ts、服务集.ts、管理集.ts |
| 装配函数 | `文游<集名>(ctx)` | 文游指令集、文游服务集 |
| 插件数组 | `<域>插件列表` | 生产插件列表、管理插件列表 |
| 表加载函数（定义在各上下文） | `加载<域>相关表` | 加载军事相关表、加载玩家相关表 |
